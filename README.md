# 芽生え

**ひらめきを置いて、つないで、広げよう。**

言葉を持ち寄り、意外な組み合わせからアイデアを育てる、共同編集型のブレーンストーミングボードです。
手が止まったときにはAIが発想の種となる言葉を追加し、神経衰弱モードではチーム全員で言葉を組み合わせてアイデアを考えます。

## 製品概要

アイデア出しで行き詰まりやすい場面を、ユーザー自身が手を動かすことで乗り越えられるように支援します。
単語を出すところから、組み合わせて発想し、整理して成果を持ち帰るところまでを、一つの共有ボードで行えます。

### 背景・課題

私たちはJPHACKSに向けたアイデア出しに想定以上の時間をかけました。
その様子を振り返ったときに、以下の二つのケースで行き詰まっていたことがわかりました。

- ブレーンストーミングのとき、何も思いつかなくなり、手が進まなくなって何もせず終了を待ってしまう
- アイデア同士を組み合わせて新しい案をたくさん出したいのに、既に考えた案についてばかり考えてしまう

また、AIに独創的なアイデアを求めて時間を浪費する場面もありました。

そこで、AIには新しい言葉を提案する役割を、人にはその言葉を解釈して組み合わせる役割を持たせました。
「何も思いつかない」「いつも同じ案に戻ってしまう」という状態から、次の一手を生み出すことを目指しています。

### 製品説明

ブラウザからルームを作成し、同じルームIDを共有するだけで、複数人が同じボードで作業できます。
一人で考えを広げる用途にも、チームでのアイデア出しにも使えます。

#### 基本機能

| 機能                        | できること                                                                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| ルームでの共同編集          | 同じルームの参加者に、カード・矢印・リアクション・タイマーの変更をリアルタイムに共有します。                                                 |
| 通常付箋                    | 単語や気づきを自由に記入。色・書体・サイズの変更、複数選択での一括移動にも対応しています。                                                   |
| 関連カード・矢印            | 複数のカードを関連付けてアイデアをまとめ、矢印でカード同士のつながりを可視化できます。                                                       |
| リアクション                | 関連カードに、👍・❤️・💡・🤔・🎉の5種類のリアクションをユーザーごとに付け外しできます。                                                      |
| AIによる候補語の生成        | Geminiが最大3つの新しい言葉を提案。手動生成では関連性を「低・中・高」から選べます。全員の手が止まったときの自動生成にも対応しています。      |
| 神経衰弱モード              | ボードの単語を裏向きのカードにし、選んだ2語から全員がアイデアを考えます。作ったアイデアは、元の2語に関連付けたカードとしてボードに残ります。 |
| 共有タイマー                | 5分のカウントダウンを共有し、開始・停止・リセットを全員の画面に反映します。                                                                  |
| JSON保存・読み込み／SVG出力 | JSONでボードを保存して後から編集を再開したり、カードやつながりをSVGで出力して成果を共有したりできます。                                      |

#### 使い方

1. [アプリ](https://ya-sheng-e.onrender.com/)で「新しいルームを作る」を押します。参加者は同じルームIDを入力するか、ルームのURLを開いて参加します。
2. 左の「付箋を追加」で通常付箋を選び、キャンバスをタップして配置します。思いついた言葉を書いて「確定」します。
3. 関連カードや矢印で言葉をつなぎ、リアクションを付けながら考えを広げます。
4. 行き詰まったら右下の「AI」から関連性を選び、「単語を生成」を押します。自動生成のON／OFFは、右上メニューの「ボード設定」で切り替えられます。
5. 本文のある通常付箋が2枚以上そろい、全員の編集が終わったら「神経衰弱をはじめる」を押します。選ばれた2語から、制限時間内にアイデアを書きます。
6. 作業後は右上メニューの「JSONで保存」や「SVGで出力」で成果を持ち帰ります。「JSONを読み込む」では、内容を確認して現在のボードを保存データに置き換えられます。

本文はEnterで改行、空白のタップまたはCtrl／⌘＋Enterで確定、Escapeで取消できます。

### 特長・課題解決

#### 1. 手が止まったら、AIが発想の種を追加

全員のカード編集が終わり、30秒間カードなどの更新がない状態を、行き詰まりのきっかけとして検知します。
自動生成がONの場合、Geminiがボード上の言葉を基に、関連性「中」で最大3つの候補語を追加します。

手動生成では、意外な分野へ広げたいときは「低」、同じジャンルで考えたいときは「中」、テーマを掘り下げたいときは「高」を選べます。
追加時には竜巻のアニメーションを表示し、画面外に追加されたカードには、その方向と移動先を示す案内を出します。

候補を追加しただけで自動生成を繰り返すことはなく、ユーザーが考えて手を動かすきっかけとして使えるようにしています。

#### 2. 神経衰弱で、思いがけない2語を組み合わせる

ブレーンストーミングで出した単語を、そのまま神経衰弱のカードにします。
担当者が10秒以内に2枚をめくり、その2語から全員が10秒間でアイデアを記入します。他の参加者の入力も途中から見られるので、互いの発想に刺激を受けながら考えられます。

盤面には最大10枚を表示し、使った分だけ次の単語を補充します。
一度に大量のカードを探し回らずに、普段なら選ばない言葉の組み合わせに向き合える仕組みです。一人でも遊べます。

記入したアイデアは元の2語と関連付けて通常ボードに追加され、ゲームを終えた後も整理や議論を続けられます。
元の単語カードの位置や関連付けは保ち、成果物にはアイデアの作者情報を残しません。

#### 3. アイデアを考える主役は、人

AIが担うのは、発想のきっかけとなる言葉の提案です。
そこから何を連想し、どう組み合わせるかはユーザーに委ねることで、一人ひとりの経験や視点をアイデアに活かします。
単語を出して終わることなく、関連カード・矢印・リアクションを使って、チームで整理し議論するところまで支援します。

### 注力したこと（こだわり等）

#### 言葉同士の「関係」を残す設計

当初はチーム名にもある「写像」を軸に考えていました。そこから、言葉と言葉の関係性そのものに着目して開発しました。
通常付箋と関連カードを分け、アイデアがどの言葉から生まれたかをたどれるようにしています。
神経衰弱で生まれたアイデアも同じモデルに接続し、ゲームの成果をその後の共同作業に活かせるようにしました。

#### 複数人で使っても、編集を上書きし合わない

カードを編集するときはサーバーから編集権を取得し、他の端末からの同時編集を防ぎます。
複数カードの移動もまとめて扱い、編集権の期限確認や無応答時の解放まで実装しました。
通信が途切れて操作結果が分からなくなった場合も、元の要求IDで結果を確認・再送し、同じ操作が二重に実行されることを防ぎます。

#### 日本語入力とタッチ操作を細部まで調整

日本語変換中の文字が画面更新で巻き戻ったり、変換のためのEnterやEscapeで編集が確定・取消されたりしないよう、入力処理を分離しました。
タッチ端末で最初のタップから入力を始められるようフォーカス管理を調整し、神経衰弱では時間切れ時に変換中の本文を確定してから最終送信します。

#### ゲームの進行と共同作業の整合性

手番・選択・入力期限をサーバーで管理し、全員に同じ進行を共有します。
途中参加、選択担当者の切断時の交代、全員切断時の終了、共有の中断確認にも対応しました。
ゲーム中は通常ボードの変更を制限し、中断時も受信済みの本文や終了時の最終入力を回収して成果を残します。

#### 保存した成果を、見た目でも構造でも持ち帰る

SVGには画面外のカードや矢印も含むボード全体を出力し、日本語・改行・関連先・リアクションも反映します。
JSONにはカードとつながりを保存し、編集権や通信状態などの一時的な情報は含めません。
読み込み時は形式や参照関係をクライアント・サーバーの両方で検証し、他の人が編集中の場合は置き換えを止めます。

### 今後の展望

- 神経衰弱以外のゲームやアイデア創出法を組み合わせ、発想の広げ方にバリエーションを持たせる。
- プロダクトの名前・画面・演出の統一感をさらに高める。
- word2vecなど、単語同士の関連性を扱う手法にも挑戦する。
- ユーザー情報の保存や、他の参加者のカーソルの可視化に対応する。
- **データの永続化・自動保存：** 現在のJSONによる手動保存・復元に加えて、サーバー側でボードの状態を永続化し、再起動後も作業を継続できるようにする。
- **リアルタイム同期の最適化：** 現在の更新番号と変更対象の識別情報を活用し、ボード全体ではなく必要な差分のみを配信することで、通信量・CPU負荷・メモリ使用量の削減を目指す。
- **ユーザー・アカウント管理：** アカウント機能を導入し、ユーザー情報や参加ルームを継続的に管理できるようにする。
- **アクセス制御・プライバシー：** 公開・非公開ルーム、招待機能、閲覧・編集権限などを整備し、利用者が安心してアイデアを共有できる環境を目指す。

継続利用に向けたデータの永続化・同期の最適化・アカウント管理・プライバシーの方向性は、[今後の設計方針](./docs/future-plans.md)にまとめています。詳細設計は同文書に順次追記します。

## 開発環境

Node.js 22.18以降の22系、または24以降を使用します。

```bash
npm install
cp .env.example .env.local
# .env.local の GEMINI_API_KEY に取得したキーを設定
npm run dev
```

[http://localhost:3000](http://localhost:3000)で起動します。Geminiの設定・デプロイ・検証コマンドは[セットアップ手順](./docs/get_start.md)を参照してください。
現在のボードは単一サーバープロセスのメモリ上で管理しており、再起動で初期化されます。残したい内容はJSONで保存してください。
