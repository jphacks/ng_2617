# 神経衰弱のゲームUI設計

更新日：2026年10月25日。会話で合意したルールを前提に、画面・操作を整理する。本書を最新の仕様とする。基本の進行に加え、中断時の入力保存、確認中の時間進行、切断時の担当交代と0人での終了、通常操作の制限、終了後のタイマー復帰まで実装済み。以下の「案」は設計時の記述で、採用した処理の詳細は末尾の「実装した境界」と [implementation.md](./implementation.md) を参照する。

## 1. 今回までに合意した前提

- 開始時にボード上の全カードをコピーし、ゲーム用カード一覧を作る。元カードのIDとの対応を保持する。
- ゲーム中は専用UIだけを表示し、通常ボードのUIは表示しない。この機能のために元カードへ表示・非表示の属性を追加したり、各カードの表示状態を変更したりする処理は設けない。
- 元カードの位置と関連はそのまま保持する。終了時は通常ボードのUIへ切り替える。開始前の表示状態の記録・復元や、ボード全体の上書き復元は不要。
- 選択対象は開始時点で本文のある単語カード。全カードをコピーすることと、すべてを選択対象にすることは別。
- 誰でも手動で開始でき、開始した人を最初の担当者にする。
- 1人でも開始できる。参加者が1人の場合は同じ人が担当を続ける。開始時にカードを編集中のユーザーが1人でもいれば開始できない。
- 担当者が2枚選ぶ時間は、手番開始から10秒。選べなければ次の担当へ交代する。選びかけの1枚は裏に戻し、未使用のまま残す。
- 2枚の確定と全員分の入力カードの準備後、全員共通で入力時間10秒を開始する。
- 全員が自分のカードに入力し、他の人の本文も入力途中から閲覧できる。他人のカードは編集できない。
- 入力用カードはゲーム進行データ内に持ち、期限後に本文のあるカードだけ通常ボードへ追加する。書きかけも残す。
- 追加するアイデアは、元の単語2枚を関連先に持つ。ゲーム用コピーを片付けても参照が残る。
- 成果物に作者情報を残さない。入力中の編集権限のためだけに、一時的なユーザーとの対応を持つ。
- 1件以上残れば元の2枚を使用済みにする。全員空なら2枚を裏に戻して再利用する。
- 参加者が複数なら次の担当は直前の担当以外からランダムに決め、1人なら同じ担当を続ける。表示中と補充待ちを合わせた未使用カードが2枚未満なら終了する。
- ゲーム進行データをボードに1つ持ち、段階・担当・選択・期限・入力カードをサーバーで管理する。
- 入力画面は左右配置とする。左側に選ばれた単語2枚と自分の入力欄、右側に他の参加者の入力を表示する。
- 選択画面のカードは10枚程度に抑える。残りの単語を補充待ちとして保持し、使用済みをゲーム盤面から外して補充する。実装上は表示枠数10を初期値にする案。
- 元ボードの物理的な配置に依存せず、未使用の単語をランダムに取得してゲームUIの枠へ入れる。元カードの座標をシャッフルする処理は不要。
- 時間切れや全員空でカードを戻す場合は、同じ表示枠で裏向きに戻す。表示中のカードを並べ替えたり、別の単語に引き直したりしない。
- 選択後の取り消し・選び直しは設けない。
- 誰でも中断を要求できる。確認を全員へ表示し、誰か1人が終了を確定すればゲームを終了する。全員の同意は必要ない。
- 作ったアイデアの通常ボード上の配置には、既存の単語生成によるカード追加と同じような経路を使う。
- 選択・入力の10秒は既存の共有タイマーを活用する。ゲーム専用の独立したカウントダウンは作らない。
- IME変換中に10秒になった場合は、その時点で変換中の入力を確定させる。
- ゲームの途中保存・途中再開は設けない。
- 中断が確定したら、入力中のカードもその時点の本文を残す。空のカードは追加しない。
- 中断確認の表示中も時間は進める。誰かが「続ける」を押したら、全員の確認表示を閉じる。
- 切断したユーザーを担当候補から外し、選択中の担当が切断した場合は接続中の人へ担当を移す。接続者が1人ならその人が続け、0人ならゲームを終了する。
- ゲーム中は通常ボードの編集・追加・削除・読み込みと、タイマーの手動操作を停止する。専用のゲーム操作による下書き更新・成果物追加は受け付ける。
- 自然終了・中断・接続者0人での終了時は、共有タイマーを通常の5分へ戻し、停止状態にする。

既存の `matching-phase-plan.md` は初期検討の記録として保持する。作者情報の保存、コピーを持たず表示だけを変える設計、選択時間が未定、開始には2人必要、ゲーム専用の独立タイマー、全カードを一度に表示する案などは、上記の合意で更新される。途中で検討した元カードごとの表示・非表示の属性と復元処理も採用せず、専用UIへの切り替えで対応する。以前の画面試作はこの追加決定を反映する前の参考であり、約10枚の補充・1人プレイ・中断・既存タイマー連携を実装済みとは扱わない。

## 2. 画面の構成案

通常ボードとゲーム画面を同じルーム内で切り替える。通常ボードの上に小さな入力ダイアログを重ねる構成にはせず、ゲーム専用の領域を確保する。

ゲーム画面は共通ヘッダーと、選択中・入力中で切り替わるメイン領域からなる。通常のカード編集ツール・AI生成・タイマーの手動停止やリセットはゲーム画面に表示しない。既存タイマーの値はゲームの残り時間として共通ヘッダーに表示する。通常ボードへの編集・追加・削除・読み込みとタイマー手動操作は、UIとサーバーの両方で止める。ゲーム専用の下書き更新・成果物追加は別の操作として処理する。

### 共通ヘッダー

| 領域 | 表示内容 |
| --- | --- |
| 左 | Idea Board、ルーム名、神経衰弱 |
| 中央 | 現在の段階。選択中なら「あなたが選ぶ番」または「○○さんが選択中」 |
| 右 | 既存タイマーによる段階ごとの残り秒数と段階名。通信状態と中断ボタン |
| 下端 | 同じ期限から計算した時間バー |

選択と入力でタイマーの位置を変えない。残り3秒以下では数字・色で強調し、点滅や大きな画面揺れは使わない。入力本文や毎秒の数字を読み上げ続けず、段階の変更と終了を通知する。

### 選択中：盤面を広く見る

- 主領域は10枚程度の表示枠とする。開始時に選択対象の単語コピーからランダムに最大10枚を取り出し、同じ寸法で並べる。元ボードの座標は使わない。既存のアイデアカードなど対象外のコピーは選択面には出さない。
- 上部に「2枚の単語を選んでください」と「0 / 2」「1 / 2」を表示する。他の人の手番では「○○さんが選んでいます」とする。
- 裏面の色・形・表示寸法を揃える。元カードの本文の長さや色から内容が分からないようにする。未公開の本文をアクセシブル名にも入れない。
- 担当者だけが操作できる。1枚目はクリックで表になり、全員に見える。選び直し・同じカードの再クリックによる解除は設けない。
- 2枚目の受理で入力へ自動で切り替える。「確定」ボタンや追加の準備カウントダウンは設けない。
- 表示枠のカードが使用済みになったらゲーム盤面から外し、補充待ちの未使用単語からランダムに取り出して空いた枠へ入れる。元の単語カードは通常ボードから削除しない。
- 補充対象・表示枠はサーバーで一度だけ決めて全員へ配信する。補充のために、残っているカードの表示枠を動かさない。候補が尽きたら無理に10枚を維持せず、残っている未使用カードだけで続ける案。
- 単語が多くても全単語をスクロールで探す方式にはしない。表示枠の未使用枚数と、補充待ちの枚数を区別して表示する案。
- 時間切れでは選びかけを同じ枠で裏に戻し、次の担当と新しい10秒を表示する。再抽選・並べ替えはしない。1人なら同じ担当の新しい手番を始める。通知のために次の期限を止めない。

### 入力中：単語と入力欄を同時に見る

左右配置で確定。左側を選ばれた単語2枚と自分の入力欄、右側を他の参加者の入力とする。

```text
┌────────────────────────────────────────────────────┐
│ Idea Board / 神経衰弱       アイデア入力中       残り8秒 │
├────────────────────────────────────────────────────┤
│                               │                      │
│  [ 選んだ単語1 ] × [ 選んだ単語2 ] │ ほかのアイデア        │
│                               │ ┌──────────────────┐ │
│  自分のアイデア                  │ │ 入力中の本文       │ │
│ ┌───────────────────────────┐ │ └──────────────────┘ │
│ │                           │ │ ┌──────────────────┐ │
│ │ テキスト入力欄               │ │ │ 入力中の本文       │ │
│ │                           │ │ └──────────────────┘ │
│ └───────────────────────────┘ │                      │
│ 自動で共有 / 時間終了で追加        │ 入力順を変えずに更新    │
└────────────────────────────────────────────────────┘
```

| 要素 | 操作・表示案 |
| --- | --- |
| 選んだ2枚 | 入力欄のすぐ上に並べる。単語が長い場合も折り返して全文を読める。2枚を参照しても入力フォーカスは失わない |
| 自分の入力 | 1枚の大きなテキスト欄。Enterは改行。送信・完了ボタンは設けず、10秒まで何度でも書き直せる |
| 保存状態 | 「共有済み」「共有中…」「未送信の変更があります」を控えめに表示。自分の本文の再描画でカーソル位置を動かさない |
| 他の人の入力 | 全員分を固定順で並べ、本文だけを更新する。空のものは「入力待ち」。並べ替えや自動スクロールで読んでいる位置を奪わない |
| 作者表示 | 「自分のアイデア」と「ほかのアイデア」を区別する。カードへの作者名・アバターの表示は設けない案。担当者名は進行案内に使う |
| 残り時間 | 選択中と同じ位置。期限で入力を閉じ、サーバーの確定を待つ間は「結果を反映中」と表示する。端末だけで次の担当へ進めない |

比較した上下配置案は採用せず、基本レイアウトは左右配置とする。左右に並べられない狭い画面でのみ、単語2枚→自分の入力→他の入力の順に積む案を別途検討する。

### 入力終了から次の手番

- 結果専用の待機シーンや「次へ」ボタンは追加しない案。サーバーの確定後に次の選択画面へ進む。
- 「3件のアイデアを追加しました。次は○○さんです」のような短い通知で結果を伝える。
- 全員空なら「今回は追加なし。2枚を裏に戻しました」と伝える。2枚は元の表示枠に戻し、他の表示枠も動かさない。
- 最新の成果物は通常ボードに蓄積される。ゲーム中に成果物を開き直す操作や、成果物一覧を常時表示する案は初期範囲に含めない。
- ゲーム終了時は通常ボードのUIへ戻し、追加したアイデアが見える範囲を表示する案。元カードの位置は変更していないため、カードごとの復元処理は不要。

### 中断の確認

1. 担当者に限らず、誰かが共通ヘッダーの「ゲームを中断」を押す。
2. 中断確認の状態をサーバーから全員へ共有し、全員に「神経衰弱を終了しますか？」を表示する。
3. 誰か1人が「終了する」を押した時点で、サーバーがゲーム終了を一度だけ確定する。要求した本人が押す必要はない。
4. その時点の入力中カードを確定し、本文のあるものを通常ボードへ追加する。既に追加済みのアイデアも残す。現在のタイマーと手番の処理を無効化し、共有タイマーを5分・停止状態に戻す。ゲーム用コピーを片付け、通常ボードのUIへ切り替える。

確認を表示している間もタイマーとゲーム進行は継続する。誰か1人が「続ける」を押すと、全員の確認表示を閉じる。確認が別の手番をまたいでも、別ゲームを終了させないようゲームIDと確認の識別子を検証する。通常の期限終了と中断が重なっても、同じ入力カードを二重に追加しない。

## 3. 人による表示の違い

| 利用者・状態 | 選択中 | 入力中 |
| --- | --- | --- |
| 今の担当者 | カードを選べる | 自分のカードに書ける |
| それ以外の参加者 | 選択を見守る | 自分のカードに書ける |
| 入力開始後の新規参加者 | 次の入力開始から配布対象になる | 「この手番は見学中。次の手番から参加できます」。他の人の入力は読める |
| 再接続した配布済み参加者 | 現在進行中のサーバー状態を表示 | 同じ手番が進行中かつ期限内なら本人分を表示。途中保存したゲームの再開や期限の延長は行わない |

本人判定は入力中の権限管理にだけ使う。結果へ入力者の対応をコピーしない。

切断したユーザーは担当候補から外す。選択中の担当が切断したら、接続中の人へ交代する。入力中は選択担当者だけの切断で他の人の入力を打ち切らず、同じ入力期限まで進める。受理済みの下書きは残す。接続者が0人になったら、受理済みの本文を基に終了処理し、ゲームを途中再開可能な状態で保持しない。

## 4. 狭い画面・入力の安定性

- PCは左の作業領域と右の共有領域を並べる。概ね760px未満では上から「単語2枚→自分の入力→他の入力」とする案。
- 単語2枚は小画面でも横並びを基本とし、長文は折り返す。タイマーと単語がソフトウェアキーボードで隠れない位置に残るよう実機確認する。
- PCでは入力段階へ切り替わったときに入力欄へフォーカスする。タッチ端末は突然キーボードを開かず、本人のタップで入力を開始する案。
- 切り替えアニメーションで入力受付を遅らせない。必要なら短いフェードだけを使い、モーション抑制設定に従う。
- 日本語変換中に期限が来た場合、その時点の入力を確定させる。入力受付を終了し、IME確定後の最終本文を取得して送信してから入力欄を片付ける設計とする。期限で先に入力欄を破棄し、変換中の本文を落とさない。
- 期限後の新しい編集は受け付けない。一方、0秒時点のIME確定に伴う最終本文はネットワーク到着が期限をまたぎ得るため、最終本文を受け取る終了処理と、カードを通常ボードへ追加する確定処理の順序を設計する。旧案の「サーバー期限到達後はすべての本文要求を即時拒否」をそのまま適用しない。
- 通信切断はヘッダーで通知する。切断した端末の選択操作は停止し、入力欄のローカル本文は維持するが未共有と表示する。ゲーム全体は接続者がいる間は続行し、選択担当の切断時は接続中の人へ交代する。再接続後は同じゲーム・手番で期限内の場合に限り送信を再開する。0人で終了済みのゲームは再開しない。

## 5. 次に実装へ落とすときの境界

- 通常ボードとゲーム画面の切り替えは共有ゲーム状態から決める。新しいページへの遷移や別ルームへの移動は不要。
- ゲーム画面内の入力欄・選択カードの位置はUIレイアウト。コピーのゲーム配置や、成果物を通常ボードに置く座標とは分ける。
- コピーの選択対象は「表示枠」「補充待ち」「使用済み」に分け、同じ単語が複数の枠や補充待ちに重複しないようにする。表示枠と補充待ちを合わせて終了を判定する。
- 開始時はサーバーがボード全体の有効な編集ロックを確認し、1件でもあれば開始を拒否する。開始ボタンにも理由を表示する。UIだけの判定にはしない。
- 選択クリックで送るのはコピーの識別子。サーバー側で元カードとの対応と現在のゲームの対象であることを検証する。
- 表示期限を過ぎても、サーバーから次状態が届くまでは旧段階の操作を受け付けない。見た目だけで抽選・成果物の追加を行わない。
- 入力本文の更新は期限を延長しない。繰り返し届く状態更新でフォーカス、入力位置、他人のカードの順序を変えない。
- 成果物は使用する元2枚を参照し、作者の対応を持たない。入力権限用の一時的な対応は終了した手番とともに片付ける。

### 既存タイマーの活用

現行の `Board.timer` は期限 `endsAt` を共有し、`src/server/board-service.ts` の `armTimer` がサーバーで0秒への遷移を予約する。`src/server/board-timer.ts` の終了フックは現在空。表示には既存のサーバー時刻補正も利用できる。

- この仕組みを選択・入力の両方へ再利用し、各段階の開始時に10,000msで設定・開始する。手番・段階・ゲームIDも検証し、旧期限の処理が次の段階へ作用しないようにする。
- 現行のサービス処理と `board-validation.ts` は5分固定なので、通常時とゲーム時で期間を扱えるよう変更が必要。表示だけを10秒に変える対応にはしない。
- 2枚目を選んだら選択用の予約を無効化し、同じタイマーを入力用の10秒で開始し直す。入力終了後や選択時間切れでは、次の担当の選択用10秒へ切り替える。
- ゲーム進行データに独立した期限をもう1つ持たせず、現在の段階の残り時間は `Board.timer` を基準にする案。最終入力の集約は段階終了の処理として扱う。
- ゲーム中は手動タイマー操作を拒否し、ゲームの段階遷移だけで設定・開始する。終了時は通常の5分へリセットして停止する。古い10秒の予約を無効化し、終了後の通常タイマーに作用させない。途中再開機能は追加しない。

### 既存の配置経路の活用

現行の `src/server/word-addition.ts` の `suggestionCards` は、既存カード全体の右端から70離した位置に、上端を揃えた縦並びで単語を作り、サービスが最新のボードへ追加・通知する。

- アイデアもこの配置・追加の経路を利用できるよう、カード配置の共通部分を切り出す案。ゲーム用UIの座標は使わず、通常ボード上の既存カード全体の配置から追加位置を決める。
- 成果物は入力カードのID・本文・元2枚への関連を保った `BlockCard` とする。単語カードを生成し直したり、AIに本文を作らせたりしない。
- 現在の単語候補の本文重複除外はアイデアには適用しない。同じ本文を書いた参加者が複数でも、本文のあるカードはそれぞれ残す。
- 現在の単語の縦間隔250をそのまま高さ330のアイデアカードへ使うと重なるため、実際のカード寸法と余白で配置する。追加済み・追加予定カード間の重なりを避ける。
- 通常ボードへの追加と通知には既存の仕組みを使いつつ、ゲームの結果追加で単語の自動生成を意図せず起動しないよう更新種別を整理する。

## 6. 実装時に調整する事項

主要なゲームルールと例外時の扱いは確認済み。以下は追加のルール確認を必要としない実装上の調整とする。

- 左右配置が収まらない狭い画面では、単語2枚・自分の入力・他の入力を上下に並べる。切り替え幅と余白は実機で調整する。
- IME確定後の最終送信の集約方法と、通信が届かない場合の終了処理を設計する。入力できる時間は10秒のままとし、最終送信のために編集可能時間を延ばさない。
- 担当交代・期限終了・中断・0人による終了が競合しても、成果物の追加と終了処理を一度だけ確定する。
- 配置、フォーカス、時間表示の更新、入力の送信頻度は、既存の通信・描画の仕組みに合わせて調整する。

## 7. 画面の確認観点

- 選択・入力で、残り時間の位置が変わらず段階を判別できる。
- 裏面や読み上げから、未選択カードの本文が分からない。
- 非担当者・入力時間外の操作ができない。使用済みカードは表示枠・補充候補から外れ、元カードの実体と関連は残る。
- 未使用が10枚を超えても表示は10枚程度に収まり、使用済みの枠へ補充される。残っている枠は動かず、全員の表示が一致する。
- 画面に2枚未満しか見えていなくても、補充待ちがある場合は補充して続行する。全体の未使用が2枚未満になったときだけ自然終了する。
- 1枚選んで時間切れになっても使用済みにならず、次の担当に同じ配置が届く。
- 1人で開始でき、選択時間切れでも入力終了後でも担当を続けられる。編集中のユーザーがいれば開始を拒否する。
- 全員が同じ単語2枚を見ながら入力でき、他人の本文更新で自分の入力位置が動かない。
- 空の下書きと書きかけを区別し、期限後は確定済みの成果物と未反映入力を区別できる。
- 途中参加者は閲覧でき、配布対象でない手番に入力欄を持たない。
- 320px幅・長い単語・多人数でも、単語・タイマー・入力欄が重ならない。
- ゲーム中は専用UIのみを表示する。元カードの位置や表示属性を変更せず、終了後は追加したアイデアと元単語への関連を保った通常ボードのUIへ戻る。
- 中断要求を全員が確認でき、要求者以外の1人が確定しても終了する。重複した確定で終了処理が繰り返されない。
- 中断時は本文のある入力中カードを残し、空のカードは破棄する。確認中も時間が進み、「続ける」で全員の確認が閉じる。
- 担当者の切断で接続者へ交代し、1人で継続できる。接続者0人なら終了し、再接続しても終了済みゲームを途中再開しない。
- ゲーム中の通常ボード変更・タイマー手動操作はサーバーでも拒否され、ゲーム専用の入力と成果物追加は動作する。
- すべての終了経路で共有タイマーが通常の5分・停止状態に戻り、ゲーム中の古い予約が作用しない。
- IME変換中に0秒になっても、その時点の入力が確定・最終送信の対象となる。期限後の新しい編集は追加されない。
- 既存タイマーの0秒処理が選択・入力の正しい段階へ作用し、旧段階の予約が次の10秒を終了させない。
- アイデアは既存の追加経路を通じて通常ボード上に重ならず配置され、本文が同じでもカードを省かない。途中保存・再開の導線は設けない。

## 8. 実装した境界

- `Board.matching` の有無で通常ボードと専用画面を切り替える。`MatchingGame` は `src/domain/matching.ts` に定義。元カード本体を変更しないコピー、10個の固定表示枠、補充待ち、使用済み、担当、手番、下書き、中断確認を共有する。候補が尽きた表示枠の末尾は描画せず、残る枠の位置は維持する。
- 進行は `selecting` → `writing` → `closing`。選択・入力とも `Board.timer` を10,000msで開始し、既存の `armTimer` と予約の世代管理を利用する。選択期限では次の手番へ進め、入力期限では入力欄を閉じる。
- `closing` は編集時間を延長しない最終送信の集約状態。入力欄をblurしてIMEを確定し、60ms後にその本文を最終送信する。サーバーは最大1,000ms待って一度だけ通常ボードへ追加する。この間の通常入力を拒否し、本人の入力権に対応する最終本文を1回だけ受理する。通信が届かなければ最後に受理した本文を残す。
- 中断確定でも同じ最終送信・追加処理を使う。確認中はタイマーを止めず、確認IDは同じゲーム内の手番をまたいで有効。「続ける」や終了済みの古い確認は他の確認・ゲームへ作用しない。0人での終了は通信を待たず受理済み本文を保存する。
- SSE購読を参加者管理に利用し、同じユーザーの複数タブは1人と数える。各入力カードは最後に接続したタブへ割り当て、切断時は残る同一ユーザーのタブへ引き継ぐ。`writerToken` と `sequence` で古い入力元や逆順の要求を防ぐ。入力権は成果物へ保存しない。
- ゲーム操作も既存のPOST APIとSSEスナップショットを使う。コマンド名・必須属性は [board-server.md](./board-server.md) を参照。ゲーム・手番・入力権・確認IDの検証と要求IDの二重実行防止を適用する。
- `word-addition.ts` の `placeAddedCards` を単語生成と共有する。実際のカード高に40pxの余白を足し、既存ボードの右へ配置する。アイデア本文は重複除外しない。ゲーム更新では自動生成を起動せず、開始前の生成途中の結果も破棄する。
- 760px以下では入力画面を縦に並べる。PCでは入力欄にフォーカスし、タッチ端末では自動フォーカスを行わない。裏面の本文をDOMやアクセシブル名へ出さず、段階変更と結果だけを通知する。
- 開発中に古いメモリサービスが残った場合は、処理前に `SERVER_RESTART_REQUIRED` を返す。必要なボードをJSON保存してから開発サーバーを再起動する。
